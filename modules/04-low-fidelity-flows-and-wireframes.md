# Module 04: Low-Fidelity Flows and Wireframes

## Concept
Low-fidelity work is where workflow and interaction logic are validated before visual polish.

## Practical guidance
- Build end-to-end flow slices for critical tasks.
- Include normal, edge, and failure states in wireframes.
- Keep annotations focused on behavior and decision points.

## Key questions
- What is the minimum screen sequence to complete each priority task?
- Where do users need system feedback or validation?
- Which steps create uncertainty or potential error?

## Artifact to create
- **Lo-fi Flow Set** (3–5 core task flows) with annotated wireframes.

## Common gotchas
- Designing only happy paths.
- Treating wireframes as static layouts instead of flow logic.
- Deferring error and empty states to handoff phase.

## Interview/workshop prompts
- “Which flow was hardest to simplify and why?”
- “How did you handle failure and recovery in the workflow?”

## Key takeaways
- Strong lo-fi design reduces late-stage changes.
- Flow-first design creates better implementation clarity.
