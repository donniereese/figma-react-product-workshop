# Module 06: High-Fidelity UI and Interactive Prototyping in Figma

## Concept
High-fidelity design should communicate product intent, not just aesthetics.

## Practical guidance
- Produce polished screens for priority flows with clear hierarchy.
- Prototype transitions that reflect real system behavior.
- Show responsive behavior for desktop baseline plus one constrained viewport.

## Key questions
- Does visual hierarchy align with decision-critical tasks?
- Are interactions clear enough for stakeholder review and developer handoff?
- Where should transitions clarify system status or progression?

## Artifact to create
- **Hi-fi Prototype Slice** covering key flows and state transitions.

## Common gotchas
- Prioritizing polish over workflow correctness.
- Using micro-interactions that imply unsupported behavior.
- Ignoring responsive breakpoints until development starts.

## Interview/workshop prompts
- “What visual choices improved usability in dense enterprise screens?”
- “How did your prototype communicate behavior to engineers?”

## Key takeaways
- Hi-fi should reinforce process logic and trust in the solution.
- Prototypes are communication tools across product, design, and engineering.
