# Module 05: Design System Thinking, Components, and Accessibility

## Concept
Business-facing interfaces require scalable component decisions and accessibility baked in early.

## Practical guidance
- Define core primitives (typography, spacing, color roles, status semantics).
- Establish component variants by task and state, not just visual style.
- Add accessibility acceptance criteria for each high-use component.

## Key questions
- Which components are reused across flows and roles?
- What states are mandatory (default, hover, focus, disabled, loading, error, success)?
- How will keyboard and screen-reader behavior be supported?

## Artifact to create
- **Component + Accessibility Spec Sheet** for the core UI set.

## Common gotchas
- Creating visual variants without behavioral rules.
- Inconsistent status language across modules.
- Retrofitting accessibility after high-fidelity completion.

## Interview/workshop prompts
- “How did component strategy improve speed and consistency?”
- “What accessibility choices affected structure or interaction?”

## Key takeaways
- Component thinking links design quality to development velocity.
- Accessibility constraints improve product robustness.
