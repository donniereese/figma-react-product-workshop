# Module 03: Information Architecture and Task Prioritization

## Concept
Information architecture in business tools must prioritize decision-critical tasks over visual complexity.

## Practical guidance
- Cluster content by task intent: monitor, investigate, act, report.
- Define navigation levels (global, local, in-context).
- Prioritize primary tasks using frequency x impact.

## Key questions
- What are the top 3 repeated tasks per role?
- What information must appear above the fold for decisions?
- Which actions require guardrails or confirmation?

## Artifact to create
- **IA Blueprint + Priority Matrix** for key tasks and screens.

## Common gotchas
- Overloading dashboards with undifferentiated data.
- Mixing admin/configuration tasks with daily operations.
- Hiding high-impact actions behind deep navigation.

## Interview/workshop prompts
- “How did task prioritization shape layout and navigation?”
- “How did you reduce cognitive load in high-density screens?”

## Key takeaways
- IA is a business decision tool, not just a sitemap.
- Task prioritization improves usability and implementation focus.
