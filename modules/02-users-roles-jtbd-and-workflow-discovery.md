# Module 02: Users, Roles, Jobs-to-Be-Done, and Workflow Discovery

## Concept
Enterprise products serve role-based workflows. You are designing for responsibilities, handoffs, and outcomes—not generic personas.

## Practical guidance
- Map primary and secondary roles (operator, approver, manager, analyst).
- Capture JTBD statements for each critical role.
- Document current flow: trigger, task sequence, handoff points, failure points.

## Key questions
- Which role initiates work and which role completes it?
- Where are bottlenecks and rework loops?
- What information is missing at key decision points?

## Artifact to create
- **Role + Workflow Map** with JTBD matrix and top friction points.

## Common gotchas
- Treating all users as one audience.
- Missing back-office or exception-handling roles.
- Ignoring edge paths (escalations, rejections, missing data).

## Interview/workshop prompts
- “Which role was most constrained and how did that shape your design?”
- “How did workflow mapping change your initial assumptions?”

## Key takeaways
- Role clarity drives better IA and better component requirements.
- Workflow discovery reveals where product value is actually created.
